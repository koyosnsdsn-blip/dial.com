# Supabase Auth が送るメールの文面（日本語）

最終更新：2026年10月15日

## 背景

- 相談者がメールアドレスで登録するとき（確認メール）、パスワードを忘れたときの再設定メールは、**Supabase Auth が自動で送る**。文面は Supabase の初期設定（英語）のままだったため、日本語に差し替える。
- 相談員・先生・クライアント管理者の招待と再送のメールは、アプリが自分で送る（日本語。`server/ops/setupMail.ts`）。こちらはここの設定を使わない。
- 文面はコード側に保管してある（`supabase/templates/*.html`）。**クラウドの Supabase には自動では反映されないので、ダッシュボードに貼り付ける。**

## 設定の手順（約5分）

1. Supabase のダッシュボードで、プロジェクト（dial.com-dev）を開く。
2. 左の **Authentication** → **Emails**（または **Email Templates**）→ **Templates** を開く。
3. 下の表の6種類について、**Subject（件名）** に「件名」を、**Message body（本文。Source／HTML の表示）** に「貼り付けるファイル」の中身を、全部貼り付けて **Save** する。

| テンプレート（画面の名前） | 件名 | 貼り付けるファイル（リポジトリ内） | 使われる場面 |
|---|---|---|---|
| Confirm sign up | 【ダイヤル.com】メールアドレスの確認 | `supabase/templates/confirmation.html` | メールアドレスで登録したとき（**ご質問の「メール登録時のメール」はこれ**） |
| Reset password | 【ダイヤル.com】パスワードの再設定 | `supabase/templates/recovery.html` | 「パスワードを忘れた方へ」から再設定するとき |
| Invite user | 【ダイヤル.com】アカウント登録のご案内 | `supabase/templates/invite.html` | ダッシュボードから直接招待したとき（アプリの招待は別の文面） |
| Magic link | 【ダイヤル.com】ログイン用のリンク | `supabase/templates/magic_link.html` | 現在は使っていない（念のため） |
| Change email address | 【ダイヤル.com】メールアドレス変更の確認 | `supabase/templates/email_change.html` | メールアドレスを変更するとき |
| Reauthentication | 【ダイヤル.com】確認コード | `supabase/templates/reauthentication.html` | 大切な操作の前の本人確認 |

4. 貼り付けるファイルの中身は、`{{ .ConfirmationURL }}`・`{{ .Token }}`・`{{ .Email }}`・`{{ .NewEmail }}` のような `{{ … }}` を**書き換えずに**そのまま貼る（Supabase が宛先ごとの値に置き換える）。
5. 確認：Authentication → Emails の「SMTP Settings」で、**Sender name** を `ダイヤル.com` にする（差出人の表示名。差出人アドレスは `dialdotcom-info@app.dsn.co.jp` のまま）。

## 確認の方法

- 新しいメールアドレス（本物で受信できるもの）で、相談者の登録画面（`/start/email`）から登録し、届いた確認メールの件名・本文が日本語であること、ボタンから確認が済むことを見る。
- 同じメールアドレスで「パスワードを忘れた方へ」から再設定メールを送り、日本語であること、リンクから新しいパスワードを設定できることを見る。
- 届かないときは、迷惑メールのフォルダと、SES が**サンドボックス**のままでないか（サンドボックスでは、SES で検証したアドレスにしか送れない）を確認する。

## 補足：リンクの有効期限

- 既定は1時間。招待メールの確認が遅れても困らないようにするなら、Authentication → Sign In / Providers → Email の **Email OTP Expiration** を延ばす（最大 86400 秒＝24時間）。延ばすかどうかはダイヤルさんの判断。
- アプリが送る招待・再送のメールの本文には、期限の時間を書いていない（設定を変えても本文と食い違わないように）。

## 補足：本人確認のためのリンクの先読みについて

- 組織のメールの安全対策（リンクの先読み）が、本人より先にリンクを開くと、1回だけ使えるリンクが使い切られることがある。アプリが送る招待・再送のメールは、リンクを開いただけでは使われず、ページの「進む」ボタンで初めて確認する作りにしてある（`/ops/accept-invite`）。
- Supabase が送る確認メール・再設定メール（上の表）は、標準の作りのまま（リンクを開くと使われる）。個人のメールアドレスが中心の相談者向けなので、当面このままにする。社内のメールアドレスで登録した人から「リンクが無効」と言われたら、この点を疑う。
