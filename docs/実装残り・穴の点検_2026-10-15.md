## 0. 点検の方法と限界（先に読む）

- 調べたもの：未決事項一覧、開発環境一覧、CLAUDE.md、git履歴、コード（pages / server / ops）、dev の実DB（RLS・権限・索引・定期処理・advisors）、Supabase の適用履歴。
- 調べきれていないもの
  - 10/1〜10/15 の会話の本文：セッションの記録に残っていない（圧縮済み）。「約束したが終わっていないこと」は、未決事項一覧・コード中のコメント・git履歴から再構成した。会話にだけ出て文書に残らなかった約束は拾えていない可能性がある。
  - 要件定義書の原本：Project 側にあり、`docs/` にあるのは要約版。章ごとの厳密な突き合わせは、確認できた範囲のみ。
  - `supabase/tests` の中身、全APIの入力検証、全テーブルの書き込み経路：網羅していない。
- 表記：【確認】＝コードかDBを直接見て確かめた。【推測】＝状況証拠のみ。
- 優先度：高＝公開前に必須・セキュリティ・データ破損の恐れ／中＝運用に必要／低＝改善。

## 1. 結論

- 骨格（相談者側・運営・クライアント管理サイト・Q&A・動画・先生コメント・IP制限・テストフラグ）は広く実装済み。画面だけあってAPIがない、というずれは見つからなかった。
- 制約#1〜#6のうち、ブラウザ側コードからの直接参照は無し【確認】（#1）、RLSは全テーブルで有効【確認】（#2）、service role は server のみ【確認】（#4）。
- 一方で、公開前に直したい穴が見つかった。**人間の判断なしに直せるもの（第2章）を先に片付け、判断が要るもの（第3章）は相談する**、という順を提案する。

最優先の5件：

1. 適用履歴と repo のマイグレーションが6本ずれている（本番昇格・stg複製で事故になる）
2. セキュリティヘッダーが無い・相談内容のAPIに `no-store` が無い
3. 相談者が見る `error.vue` が無い（想定外エラーで英語のページが出る）
4. クライアント管理者が、同じクライアントの別の管理者のパスワード再設定リンクを取得できる（アカウント乗っ取りになりうる）
5. DBの索引が足りない（`messages.case_id`、`cases.counselor_id` など）
