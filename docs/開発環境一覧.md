## Vercel（チーム：kokyosns／Hobby）

| プロジェクト名 | 対象アプリ | Root Directory | URL |
|---|---|---|---|
| dial.com-op-dev | 相談者側 | `apps/consultation` | https://dialcom-op-dev.vercel.app |
| dial.com-admin-dev | 管理側 | `apps/admin` | https://dialcom-admin-dev.vercel.app |

- 両プロジェクトとも GitHub `koyosnsdsn-blip/dial.com` の `main` ブランチに連携（push で自動デプロイ）
- 関数リージョン：`hnd1`（東京）。`vercel.json` の `regions` で指定
- 環境変数：`SUPABASE_URL`・`SUPABASE_ANON_KEY`（Production と Preview）
- `SUPABASE_SERVICE_ROLE_KEY`：**管理側（dial.com-admin-dev）の Production のみ**に設定する。相談者側・Preview には置かない（CLAUDE.md 制約#4）。未設定だと案件の一覧・詳細APIは 503 を返す（監査ログを記録できないため）
- 動作確認：`/api/health` で `region` が `hnd1`、`supabaseConfigured` が `true` になることを確認済み（2026-09-30）

- 任意の環境変数（管理側）：`CRON_SECRET`（添付画像の定期消去）、`USER_SITE_URL`（相談者側のアドレス。ランディングページの URL の表示に使う。既定は dev のアドレス）、`LLM_API_ENDPOINT` / `LLM_API_KEY` / `LLM_MODEL`（未設定でよい。設定しても、方式が決まるまで相談内容は外部へ送らない）

## 今後の注意

- 本番用の Vercel プロジェクトを同じリポジトリにつなぐときは、dev と本番でデプロイ対象ブランチを分ける（例：dev＝`develop`、本番＝`main`）。分けないと `main` への push で両方にデプロイされる
- 本番化の際は Supabase を有料組織のプロジェクトへ移すため、URL・キー・Vercel の環境変数がすべて変わる
